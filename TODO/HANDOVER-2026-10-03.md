## How to build, test and deploy

- **Laptop**: `cmake --build build -j`, then `./build/macha-tests` and
  `./build/macha-tests-runtime` (the lifecycle fixtures live in the
  runtime binary). `--filter X` (substring), `--repeat N`, `--jobs N`,
  `--verbose`; `MACHA_TEST_LOG_LEVEL=DEBUG` for a failing case's log.
  `macha-tests-torrent` cannot host a libtorrent session on the laptop (5
  of 21 segfault in any build): it runs on fi-1.
- **Coverage**: `./run-coverage.sh [build-coverage] [-- --filter X]`
  (Debug). Works on the laptop since 2026-10-01; fi-1's GCC run is the
  canonical one.
- **Commit only on a clean suite**: gate `git commit` on both suites'
  exit codes (2026-10-02: a commit was pushed after a failed run).
- **Test a few times and be done** (operator, 2026-10-02): a new or fixed
  test runs a few times; no repeat-hundreds runs or mutation sweeps by
  default.
- **A test never depends on real time.** A test that needs a scaled or
  longer wait is a faulty test (operator, 2026-10-01): drive the step (an
  explicit call, durable floors so a commit is everywhere on return, the
  manual clock and `settle`), and wait only on events with a hang guard.
- **fi-1 builds; never build on gbni-1.** Sync without `--delete`:
  ```
  rsync -a --exclude='.git' --exclude='build' --exclude='build-*' --exclude='.cache' \
    --exclude='.DS_Store' --exclude='.claude' --exclude='.codegraph' --exclude='*.swp' \
    --exclude='*.tmp' --exclude='CLAUDE.md' /Users/tom/devroot/macha/ root@10.35.1.10:/root/macha/
  ssh root@10.35.1.10 'cd /root/macha && rm -f /root/build.log /root/suite.log && (setsid nohup sh -c "nice -n 10 cmake --build build -j3 > /root/build.log 2>&1; echo BUILD_RC=\$? >> /root/build.log; sh run-tests.sh build > /root/suite.log 2>&1; echo SUITE_RC=\$? >> /root/build.log" >/dev/null 2>&1 </dev/null &)'
  ```
  Poll for `SUITE_RC=`, and check `BUILD_RC` too.
- **Versions**: plain semver; `project(macha VERSION ...)`, the `*vX.Y.Z*`
  line in `README.md` and `macha.yaml.example`'s header move together;
  CHANGELOG entry.
- **Ship and install** (as done for 0.75.0 on 2026-10-02):
  ```
  ssh root@10.35.1.10 'rm -rf /tmp/stage-V && cd /root/macha && DESTDIR=/tmp/stage-V cmake --install build >/dev/null && tar czf /tmp/macha-V.tgz -C /tmp/stage-V usr && md5sum /tmp/macha-V.tgz'
  ssh root@10.35.1.10 'cat /tmp/macha-V.tgz' | ssh root@10.44.1.50 'cat > /tmp/macha-V.tgz'
  ssh root@<node> 'TARBALL=/tmp/macha-V.tgz BACKUP=/root/macha-<prev>-installed.tgz bash -s' < build/install-guarded.sh
  ```
  The script backs up once, installs, waits 150 s for health and rolls
  back by itself on a crash loop or no health. After a rollback on gbni-1,
  restore its heap-check drop-in from `/root/heap-check.conf.keep`.
  `build/claude-viewers.sh` before an install or heavy build; fi-1 first,
  then gbni-1, 5-10 minutes apart. The operator may say to ignore viewers
  (2026-10-02, for a failover test).
- **The rsync never deletes**: a file removed from the tree stays on fi-1
  and is compiled if CMake still lists it. Remove it there by hand
  (2026-10-02: `src/component/`, `tests/test_component.cpp`).
- Scratch files go in `build/` (gitignored), never `/tmp` or the session
  scratchpad: both are outside the permitted trees. Reading outside them
  (e.g. `/usr/local` headers) needs the operator's word each time.

## Traps

- **basemind for every code query**, not grep or sed; rescan after edits.
  The MCP server may not load: the CLI (`basemind -q code grep|outline|
  symbols ...`, `NO_COLOR=1`) works.
- **Report findings before fixing**; prove a mechanism before editing.
- **A failing test is P0 work.** Reproduce it on the parent commit before
  deciding whose it is.
- **Do not gate lower-class work; pace it.** State the laws a scheduling
  change touches.
- **Client sessions may ask; they do not decide.** An API change waits on
  the operator; a relayed approval is not approval (a relayed "no" is
  simply not building).
- **The API is to be RESTful** (ACTIVE 16): design every route as resource
  plus method.
- **The DATA store is `StoragePool`** over one `LocalStore` per backend;
  the control store is a `LocalStore`.
- **Service accessors wait for the asynchronous start**
  (`wait_services_ready()`); `node()` does not need to. Everything built
  after local state recovers lives in `NodeServices`.
- **Check the branch before cutting one.** The operator sometimes commits
  in this checkout (2026-10-02: a commit on `-t5`, cherry-picked to `main`,
  HEAD left on `main`); a branch cut without looking came from `main`.
- **Never edit sources under a running build or mutation run**: mixed
  objects (250 segfaulting cases from one header) or a mutant left in place
  when a run is killed. Check `git diff` after stopping one.
- **No framework-style injection** (operator, 2026-10-02): the composition
  root is code -- concrete classes, constructor references, dependency
  order written down.
- **A same-second mutation restore can skip the rebuild**: remove the `.o`.
- A stale git worktree entry points into an old session scratchpad under
  `/private/tmp`: outside the permitted trees, leave it alone.
- **The operator is a ~30-year systems architect.** His process choices
  (no CI, sanitizers as debuggers, prescriptive discipline) are deliberate.
