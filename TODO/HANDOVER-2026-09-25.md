## How to build and deploy now

fi-1 builds; **never build on gbni-1** (it browns out). fi-1 already has the
build dependencies, the tree at `/root/macha`, and `build/` configured with
`-DCMAKE_INSTALL_PREFIX=/usr` (the nodes run from `/usr`; a default
`/usr/local` build would also compile the wrong plugin directory into the
binary).

1. Bump `project(macha VERSION ...)` in `CMakeLists.txt`, the `*vX.Y.Z*` line
   in `README.md` (configure refuses a mismatch) and the header of
   `macha.yaml.example`; add the CHANGELOG entry. **A change that makes a
   request 0.x accepted fail is a minor bump, not a patch** (0.57.1 had to
   be renumbered 0.58.0).
2. Commit on `develop`, naming files (never `git add -A` or a whole
   directory: `git add docs/` swept an operator's unrelated proposal into
   `7c44643`). Push.
3. Sync and build on fi-1:
   ```
   rsync -a --exclude='.git' --exclude='build' --exclude='build-*' --exclude='.cache' \
     --exclude='.DS_Store' --exclude='.claude' --exclude='.codegraph' --exclude='*.swp' \
     --exclude='*.tmp' /Users/tom/devroot/macha/ root@10.35.1.10:/root/macha/
   ssh root@10.35.1.10 'cd /root/macha && (setsid nohup sh -c "cmake --build build -j3 > /root/build.log 2>&1; echo BUILD_RC=\$? >> /root/build.log; sh run-tests.sh build > /root/suite.log 2>&1; echo SUITE_RC=\$? >> /root/build.log" >/dev/null 2>&1 </dev/null &)'
   ```
   A version bump is a near-full rebuild (~15 min) plus ~2 min of suites.
   Poll `grep RC= /root/build.log` from a background loop; do not hold an ssh
   session open on the nohup (it hangs). Read the suite summary before
   deploying: main, runtime and torrent binaries, and the torrent **swarm
   test must pass on fi-1** (it cannot run on the laptop).
4. Stage, ship, verify:
   ```
   ssh root@10.35.1.10 'rm -rf /tmp/stage-V && cd /root/macha && DESTDIR=/tmp/stage-V cmake --install build && tar czf /tmp/macha-V.tgz -C /tmp/stage-V usr && md5sum /tmp/macha-V.tgz'
   ssh root@10.35.1.10 'cat /tmp/macha-V.tgz' | ssh root@10.44.1.50 'cat > /tmp/macha-V.tgz'
   ```
   Check the md5 on gbni-1 matches, and that the stage has
   `usr/bin/macha`, `usr/lib/macha/libmacha_core.so` and
   `usr/lib/macha/plugins/libmacha-torrent.so`.
5. Install, fi-1 then gbni-1, one after the other:
   ```
   cp -p /etc/macha/macha.yaml /etc/macha/macha.yaml.bak-<previous>
   systemctl stop macha && tar xzf /tmp/macha-V.tgz -C / && systemctl daemon-reload && systemctl start macha
   ```
   then wait for `curl -s http://127.0.0.1:7438/api/v1/health` to say
   `"ok"` with the new version, and check the journal for `metadata
   availability changed state=writable` (fi-1 turns writable only once
   gbni-1 is back) and, on gbni-1, `torrent disk backend threads=2`.
   `tools/gated-install.sh` does the same behind the 30-minute playback gate
   when a gate is wanted.
6. Tag `V` (annotated, `V: <subject>`) on the release commit, fast-forward
   `main`, push both and the tag. Tell Core the version per node; Core relays
   to the clients.

repo `macha-ts` = macha-core-npm), Macha Client (web), Macha Android TV RN
Client, Macha Mobile Phone Client. Reach them with SendMessage; address by the
`from=` socket of their last message.

- **Every change to what the API sends or accepts** is announced to Core
  (and through it every client) with the version and exact wire shape,
  **before or with the deploy**.
- Core owns the server interaction behind the combined match-or-edit
  interface and builds against a route only once its version is named.
- The server supplies facts and operations and does what it is told: no
  server pick of file, stream, container or mode (operator, 2026-09-24).
  Clients choose from `GET /api/v1/playback/media?item_id=` and play by
  `media_id`.
- Law numbering is shared by every project (1 control, 2 viewer, 3 loader,
  4 do not shoot thyself in the foot); texts may differ per repo.

## Reading a crash

gbni-1 writes cores to `/mnt/diskB/crash/core.<exe>.<pid>.<time>`
(`kernel.core_pattern` and `debug.exception-trace=1` are runtime settings,
**lost on reboot** -- gbni-1 has power failures; re-apply with `sysctl -w`,
or ask the operator about making them persistent; the systemd drop-in
`/etc/systemd/system/macha.service.d/core-dumps.conf` with
`LimitCORE=infinity:infinity` survives). To read a core, unpack the tarball
of the version that crashed into a sysroot and point gdb at it:

```
cd /mnt/diskB/crash && r=root-V && mkdir -p $r/usr/lib && tar xzf /tmp/macha-V.tgz -C $r
ln -s /lib $r/lib && ln -s /usr/lib/aarch64-linux-gnu $r/usr/lib/aarch64-linux-gnu
gdb -batch -nx -ex "set sysroot /mnt/diskB/crash/$r" -ex "bt 30" $r/usr/bin/macha <core>
```

Binaries are unstripped but have no DWARF: frames show function names only.
