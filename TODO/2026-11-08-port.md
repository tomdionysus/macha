## What the port is, in the operator's words

- **The aim:** "Dannan and Dagda are generalisations of macha's cluster and storage layer. The intent is to devlop
  them to the point where they are at least as capable as the macha code they are based on, then replace the macha
  code with them. MachaDFS and cluster become systems implemented with Dannan and Dagda as fundamental libraries.
  The fidelity point is that after that, Macha should work just as well as it ever did." The test is capability and
  how well Macha works, not its internals.
- **No conditions:** the libraries answer Yes unconditionally or keep working: "Amendments aren't acceptable.
  Development will continue on them with macha code frozen until they can answer Yes unconditionally, the entire
  reason for their existence is this."
- **Who builds it:** "R2 should be built by this agent, when the dannan and dagda agents have finished all tasks and
  reported their capabilities, and this agent is satisfied that macha can be ported with no loss of functionality
  onto their codebases, which will be frozen during the port."
- **The review:** "you are the review." This session's judgement is the gate before the port.
- **A defect found during the port:** "The port will pause until the relevant agent has identified and fixed the
  fault, with testing. The port will then continue with the relevant codebase frozen again."
- **Proving it:** "We will convert macnessa and inverbeg store backends and install there to test, prove and
  iterate." The live nodes are the test bed. No spare hardware, no disk copy, no separate timed run.
- **Macha's freeze** holds until the port starts, "because the other agents need to see stable code".
- **Torrent** stays through the port: its 23 requests, the SM19 section, DLT9 and the dump gate stand. Moving it
  out comes after all of this, "until I ask again".
- **Not gates, not to be raised:** macnessa's stability and undervoltage; the heap corruption, left until after the
  port.
- **Earlier rulings that stand:** two cutovers, transport first, then the disk; stages, inverbeg first; a Macha case
  may retire against a named library case, recorded case by case; the reverse migration is built but not a gate;
  every call names its deadline (Dannan's A); Status thread rows change (B); a per-pool thread CPU reporter (C);
  Macha's budgets representable in Dannan's layer (D); generic class admission (`sched::ClassWaits`) before stage
  one; custody from a systemd credential, one state directory, Macha's `state_path`; Macha's maintenance loop until
  8c, then Dagda's; "test once" per gate.

## The order

1. Both libraries finish all their tasks and send a capability report with evidence.
2. **This session reviews both**, reading their code, not only their reports and case counts: reading found two
   real faults in Dannan's 0.5.0 that its gates had not.
3. When satisfied, both libraries freeze at a tag, and this session builds the port on a branch of Macha's
   `develop` at or after `98b816d` (0.93.5).
4. The store backends on macnessa and inverbeg are converted and the port installed, inverbeg first, then tested,
   proved and iterated against the baselines.

## What the port must do, collected from the libraries

**Dannan (first cutover).** Register Macha's message numbers from 512 with payloads unchanged; retire 549, 550, 560,
636 (`Routes::retire`); hosted telemetry ids 1024 to 1045; every call names its deadline; `metadata_notice` on
`Registration::on_session`, never waiting (F10); the three metadata mutations registered `ordered`;
`SupervisorOptions::system_name = "macha"`; `NodeConfig::inbound_journal_fields` for `hosts_extents=`;
`fit_memory_limit` or keep `validate` with the limit 0 (F18); a gateway in `NodeConfig::gateway` for UPnP (F4);
the io thread count set deliberately; wrap `io_context::run` knowing what an escaped exception does. Macha's own by
finding: F7 topology from `Nodes::watch`, F8 activity clocks, F9 construction order and `.dannan.lock`, F11 version,
F17 the importer's locks, F21 the replicas advert reader, F22 plugins rebuilt, the 12 journal lines Dannan does not
write, failing closed on `metadata_write_replicas_required`, pacing repair by peer viewers. The facade writes
`dagda/capacity`, `dagda/used` and `dagda/extents` itself until stage one; `dannan-import-macha` converts the roster,
inbound and telemetry files and keeps `*.macha` for rollback.

**Dagda (stage one, then 8c).** The facade removes every number Dagda registers (515, 516, 517, 525, 531, 532, 534,
535, 544, 552, 557, 559, 561, 615, 616, 619, 630, 633, 635, 637, 768, 769, 770) from Macha's own registrations at
stage one; `write_copies` 1 set explicitly (Dagda's default is 2); a `ReachabilityProvider` registered, with
`known_generation` from `Exchange::known_generation`; never `Objects::remove` on Macha's paths (it has no grace);
Macha's metadata code given Dagda's control store (a type adapter for `LocalStore&`); `.macha.lock` held by Dagda's
`Node` only; `startup.data_storage_degraded` read from `dagda.storage.degraded`; `heads.reconcile_us` and
`reconcile_wait_us` mapped to Macha's `metadata.reconcile_*`; from the later stage, Macha's numbers as
`NodeOptions::exchange.numbers`, `SpaceSpec::unaddressed`, and names for `generation_advert` and
`write_copies_advert`; Macha's merge behind `heads::Merge`. Custody provisioned by Macha's deploy (the wrap advert is
optional, so no certificate is needed at stage one).

**Rollback.** Macha's binary comes back only after `dagda-migrate --reverse` has finished: Macha's history reader cuts
a Dagda-sealed or half-migrated `history.log` as one torn tail. Dannan's state files come back from `*.macha`.

**Owed to the port by the libraries' own account:** Macha's merge proved hash for hash (Dagda proved it on one
fixture only); replay of delta frames through Macha's codec; everything end to end, Status bytes and the widened
goldens; performance against the baselines; a real state imported and started.
