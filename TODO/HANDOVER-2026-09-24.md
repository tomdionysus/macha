The plan is `TODO/2026-09-23-torrent-disk-backend-plan.md`. Stages 1 and 2

queue overflowed`. Write any watcher's log inside the repo (e.g.

## Traps that cost time today

- **Filesystem boundary.** Only `/Users/tom/devroot` and `~/.claude`.
  Background task output lands in `/private/tmp/...`; do not read it --
  have the command write its own log under `build/` instead. Do not open
  Homebrew headers under `/usr/local`; libtorrent 2.0.11's source is checked
  out at `/Users/tom/devroot/reference/libtorrent-2.0.11` for reading.
- **The viewer check.** Counting recent stream lines misses a paused viewer
  (gbni-1 was restarted under one); a pipeline reclaim is not a session end;
  sessions end silently 30 minutes after last use. Use the gate script, and
  gate a gdb attach on it too.
- **Rebuild everything** when a struct shared by core and a plugin changes.
- **Delete the object file** when restoring a mutated source.
- **Python edit scripts** that assert one occurrence will refuse a pattern that
  also matches inside a deeper-indented line; anchor with `(?m)^`.
- libtorrent differs between 2.0.11 (nodes) and 2.1.1 (laptop): `status_t`,
  `disk_buffer_holder`, `free_multiple_buffers`, `storage_params`,
  `create_torrent`. The backend and its tests carry version shims.
