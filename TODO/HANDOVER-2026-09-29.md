## What changed today

- **0.72.0-0.73.1: repair actually moves data.** Four stacked causes, each
  measured before fixing: credit gated finding work as well as moving it;
  held retention claims each spent an extent of credit; the bandwidth
  estimate averaged small objects' round trips (~20 KB/s on a 1.3 MB/s+ path)
  and 0.72.0 charged every push a full extent; one push in flight at a time.
  Also: probes are validated batches (`have_valid_objects`, the operator's
  choice to keep checking the peer's copy), and the pass keeps its place
  across generations and restarts (`state/repair/push-position`).
- **A regression, caught and reverted before it shipped:** 0.73.0 as first
  written held repair while a peer served viewers. The operator: repair must
  always proceed at low priority; nothing waits for viewers to stop, and
  repair that does not happen makes a later viewer wait. It now feeds a
  peer's viewer traffic into the existing pacer. Memory rule
  `feedback_pace_never_gate.md`; standing rule in ACTIVE.
- **Per-class cluster traffic** (`nodes[].traffic`: `as_of_unix_ms`,
  `window_ms`, per class in/out bytes and bytes/s). Shape agreed with the web
  client, announced to Core and every client; Core typed it.
- **0.73.2:** `GET /api/v1/torrents/jobs` took 0.6-1.7 s on fi-1 because the
  HTTP thread surveyed peers' accepted heads (proved with gdb stacks, not
  inferred). It now serves the in-memory snapshot like the catalogue does.
  Other HTTP paths still call `snapshot_view()` (ACTIVE item 2).

## How to build and deploy

As in the 2026-09-27 handover, with these changes:

- The laptop build is `cmake --build build -j8`, then
  `./build/macha-tests`; repeat a group with `--filter X --repeat N`.
  Mutation-prove every new test (break the fix, see it fail, restore, rm the
  `.o`). Warnings are errors, so a mutation that leaves a variable unused does
  not compile and the old binary "passes": check the build output.
- fi-1: rsync (add `--exclude='CLAUDE.md'`), then
  `nice -n 10 cmake --build build -j3` and the three suites
  (`macha-tests`, `macha-tests-runtime`, `macha-tests-torrent`) in one ssh.
  Today: 595 + 15 + 21.
- Config check before any restart after a config edit:
  `/tmp/claude-config-check /etc/macha/macha.yaml` on fi-1. gbni-1's copy of
  the checker is stale (it refuses `node_name`); validate gbni-1's config by
  piping it to fi-1's checker.
- Viewer check: `ssh root@<node> 'bash -s' < build/claude-viewers.sh`.
- Install: `ssh root@<node> 'TARBALL=/tmp/macha-V.tgz BACKUP=/root/macha-<prev>-installed.tgz bash -s' < build/install-guarded.sh`
  (restores the backup if the node restarts or is not healthy in 150 s).
- Repair and traffic at a glance: the scratch script used today read
  `status/diagnostics` `repair` and `status` `nodes[].traffic` with the
  `claude` account; it printed node-local time. Compare in UTC.

## Traps that cost time today

- **Do not gate lower-class work; pace it.** See above. State the laws a
  scheduling change touches before proposing it.
- **Check the claim before stating it.** Wrong today and corrected: "the disk
  failed" (it was the USB link), "1.3 MB/s is the link" (one TCP stream),
  "the UAS driver" (it was `usb-storage` all along), "torrent writes slow the
  API" (a peer survey in the request), "the resume lost progress" (a
  local-time misread).
- **A device that drops off leaves the mountpoint empty.** Macha refuses to
  create a missing backend path, so nothing lands on the SSD under it; check
  anyway (`ls` the unmounted directory) before remounting.
- **`systemctl restart` of both nodes** interrupts torrents briefly and resets
  nothing else; repair resumes from the saved position.
