## How to build, test and deploy

- **Laptop**: `cmake --build build -j`, then `./build/macha-tests`
  (`--filter X`, `--repeat N` up to 100, `--jobs N`, `--verbose`;
  `MACHA_TEST_LOG_LEVEL=DEBUG` for a failing case's log). Sanitizer builds:
  `build-asan/`, `build-tsan/` (`MACHA_SANITIZE`). The laptop cannot host a
  libtorrent session: `macha-tests-torrent` runs on fi-1.
- **Mutation-prove every new test**: scripts in `build/claude-*-mutate*.py`
  apply one mutation, rebuild, run a group, restore and remove the `.o`.
  Warnings are errors, so a mutant that leaves a variable unused does not
  compile: rewrite it.
- **fi-1 builds; never build on gbni-1.** Sync without `--delete`:
  ```
  rsync -a --exclude='.git' --exclude='build' --exclude='build-*' --exclude='.cache' \
    --exclude='.DS_Store' --exclude='.claude' --exclude='.codegraph' --exclude='*.swp' \
    --exclude='*.tmp' --exclude='CLAUDE.md' /Users/tom/devroot/macha/ root@10.35.1.10:/root/macha/
  ssh root@10.35.1.10 'cd /root/macha && rm -f /root/build.log /root/suite.log && (setsid nohup sh -c "nice -n 10 cmake --build build -j3 > /root/build.log 2>&1; echo BUILD_RC=\$? >> /root/build.log; sh run-tests.sh build > /root/suite.log 2>&1; echo SUITE_RC=\$? >> /root/build.log" >/dev/null 2>&1 </dev/null &)'
  ```
  Poll for `SUITE_RC=`, then check `BUILD_RC` as well as the suite: a
  failed build leaves the suite running the previous binaries. fi-1's tree
  has no git, so its builds stamp `+unknown`.
- **Versions**: plain semver; `project(macha VERSION ...)` in
  `CMakeLists.txt`, the `*vX.Y.Z*` line in `README.md` (configure enforces
  it) and `macha.yaml.example`'s header move together; CHANGELOG entry.
- **Ship**:
  ```
  ssh root@10.35.1.10 'rm -rf /tmp/stage-V && cd /root/macha && DESTDIR=/tmp/stage-V cmake --install build >/dev/null && tar czf /tmp/macha-V.tgz -C /tmp/stage-V usr && md5sum /tmp/macha-V.tgz'
  ssh root@10.35.1.10 'cat /tmp/macha-V.tgz' | ssh root@10.44.1.50 'cat > /tmp/macha-V.tgz && md5sum /tmp/macha-V.tgz'
  ```
- **Before any install, restart or heavy build on a node**: viewers,
  `ssh root@<node> 'bash -s' < build/claude-viewers.sh`.
- **Install**: `ssh root@<node> 'TARBALL=/tmp/macha-V.tgz BACKUP=/root/macha-<prev>-installed.tgz bash -s' < build/install-guarded.sh`
  (restores the backup if the node is not healthy in 150 s; its rollback
  deletes gbni-1's heap-check drop-in, so restore it from
  `/root/heap-check.conf.keep`). fi-1 first, then gbni-1, 5-10 minutes
  apart. A protocol change needs both back to back.
- **Config check** before a restart after a config edit:
  `/tmp/claude-config-check /etc/macha/macha.yaml` on fi-1 (gbni-1's copy is
  stale: pipe gbni-1's config to fi-1's checker).
- `journalctl --since` takes local time (BST on gbni-1, EEST on fi-1).
- Scratch files go in `build/` (gitignored), never `/tmp` or the session
  scratchpad on the laptop: both are outside the permitted trees.

## Traps

- **basemind for every code query**, not grep or sed; rescan after edits.
- **Report findings before fixing**; prove a mechanism before editing.
- **A failing test is P0 work.** Reproduce it on the parent commit before
  deciding whose it is (`git worktree add ../macha-wt-<sha> <sha>`, build,
  same `--repeat`), then find the mechanism.
- **Do not gate lower-class work; pace it.** State the laws a scheduling
  change touches.
- **The DATA store is `StoragePool`** over one `LocalStore` per backend
  (`NodeRuntime::local_store()`); the control store is a `LocalStore`.
- **Service accessors wait for the asynchronous start**
  (`wait_services_ready()`); `node()` does not need to.
- **A same-second mutation restore can skip the rebuild**: remove the `.o`.
- A stale git worktree entry points into an old session scratchpad under
  `/private/tmp`: outside the permitted trees, leave it alone.
- **The operator is a ~30-year systems architect.** His process choices (no
  CI, sanitizers as debuggers, prescriptive discipline) are deliberate.
