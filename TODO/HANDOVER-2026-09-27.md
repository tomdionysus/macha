## What changed today, in one paragraph each

**Torrents belong to the cluster (0.64.0).** An add is a request in metadata
(`MetadataSnapshot::torrent_requests`, `src/torrent_request.{hpp,cpp}`), merged
as a join per field. `TorrentCoordinator` (`src/torrent_coordinator.cpp`, core,
one per node) takes adds and actions and, on a torrent-capable node, runs the
scheduler: claims (rendezvous-ranked, 30 s per rank), drives the local plugin
under the request id (`TorrentService::adopt`), writes phases back, takes over
claims lapsed 10 min, lets go of superseded ones, removes completed jobs after
`remove_after_ms`, and migrates pre-0.64 local jobs. `ClusterJobView`
(`src/cluster_jobs.cpp`) polls every peer's live torrent state and ingest jobs
every 5 s so no list waits on the WAN. Spec and client review:
`TODO/2026-09-27-cluster-torrent-queue-plan.md`.

**Threads (0.63.0).** Every thread site chooses `run_supervised_loop`,
`_once` or `_escalating` (`src/supervised.hpp`); faults are in Status
`threads`. The torrent plugin's worker escalates to the subsystem supervisor.

**Prompt replication (0.64.1)** skips owners without gossiped room and gives
up after five refusals; `diagnostics.prompt_replication`.

## How to build and deploy

fi-1 builds; **never build on gbni-1**. fi-1 has the tree at `/root/macha`
and `build/` configured with `-DCMAKE_INSTALL_PREFIX=/usr`.

1. Bump `project(macha VERSION ...)` in `CMakeLists.txt`, the `*vX.Y.Z*` line
   in `README.md` and the header of `macha.yaml.example`; CHANGELOG entry. A
   change that makes a request 0.x accepted fail is a minor bump; a metadata
   or wire format change needs the protocol question answered.
2. Local: `cmake --build build -j8` then `sh run-tests.sh build`. The laptop
   cannot host a libtorrent session: five `torrent_disk_io` tests segfault
   there (known, ACTIVE 15); they run on fi-1.
3. Sync and build on fi-1 (GCC catches what clang does not, e.g.
   `-Wdangling-reference`):
   ```
   rsync -a --exclude='.git' --exclude='build' --exclude='build-*' --exclude='.cache' \
     --exclude='.DS_Store' --exclude='.claude' --exclude='.codegraph' --exclude='*.swp' \
     --exclude='*.tmp' /Users/tom/devroot/macha/ root@10.35.1.10:/root/macha/
   ssh root@10.35.1.10 'cd /root/macha && rm -f /root/build.log /root/suite.log && (setsid nohup sh -c "cmake --build build -j3 > /root/build.log 2>&1; echo BUILD_RC=\$? >> /root/build.log; sh run-tests.sh build > /root/suite.log 2>&1; echo SUITE_RC=\$? >> /root/build.log" >/dev/null 2>&1 </dev/null &)'
   ```
   Wait with a background loop polling `grep SUITE_RC= /root/build.log` every
   30 s, then `grep -E "^All |FAIL" /root/suite.log` **and** `grep BUILD_RC`:
   a failed build leaves the suite running the previous binaries.
4. Commit on `develop` naming files (never `git add -A`), push.
5. Stage and ship:
   ```
   ssh root@10.35.1.10 'rm -rf /tmp/stage-V && cd /root/macha && DESTDIR=/tmp/stage-V cmake --install build >/dev/null && tar czf /tmp/macha-V.tgz -C /tmp/stage-V usr && md5sum /tmp/macha-V.tgz'
   ssh root@10.35.1.10 'cat /tmp/macha-V.tgz' | ssh root@10.44.1.50 'cat > /tmp/macha-V.tgz && md5sum /tmp/macha-V.tgz'
   ```
6. **Gate on playback in the same command as the install** (it caught a live
   viewer on gbni-1 on 2026-09-27; the operator then chose to deploy):
   `journalctl -u macha --since -3min | grep -cE "playback stream segment|pipeline direct|session create"`
   must be 0, else stop and ask.
7. Install fi-1 then gbni-1: back up `/etc/macha/macha.yaml` as
   `.bak-<previous>`, `systemctl stop macha`, `tar xzf ... -C /`,
   `daemon-reload`, `start`; wait for `/api/v1/health` to show the version and
   `metadata availability changed state=writable` in the journal.
8. Tag `V` (annotated, `V: <subject>`), fast-forward `main`, push both and the
   tag -- only on the operator's go. Tell Core the version per node.

## Traps that cost time today

- **Measure before attributing.** fi-1's 300+ ms round trips were blamed on
  prompt replication; with the stream stopped they were unchanged. The site
  link is congested by something outside Macha.
- **Take stacks of the slow thing.** The 13.8 s clear defeated five
  hypotheses until gdb samples taken during a reproduced clear showed
  `unlinkat` in `__wait_on_buffer` on a saturated DATA disk (the publisher's
  16 MB/s each way).
- **Pre-C++23 range-for over a temporary's member dangles**
  (`for (x : parse(...).find("jobs")->asArray())`).
- **`available_snapshot_view()` is empty until something has written or read
  metadata** on a bare test node; use `snapshot_view()` (which reads) where a
  current view is needed.
- `journalctl --since` takes local time (BST on gbni-1, EEST on fi-1), not UTC.
- Background task output lands under `/private/tmp`, outside the filesystem
  boundary: have commands write their own logs under `build/` and read those.
