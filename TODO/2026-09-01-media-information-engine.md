# Dedicated media-information engine checkpoint

Date: 2026-09-01

Status: implementation, local verification and four-node deployment complete;
live playback latency UAT remains in `ACTIVE.md`.

## Contract implemented

- Media profiles are advisory optimisation data keyed by the exact immutable
  `macha:` file identity, not by mutable paths or human catalogue IDs.
- Ingest, catalogue matching and profile GET submit durable hints to one
  event-driven worker. The worker sleeps without polling when it has no work.
- Hints are deduplicated and priority ordered internally. All optional scanning
  uses the global speculative data class, below loader work.
- Playback negotiation reads a valid persisted profile first and passes that
  exact normalized probe result to the existing Direct/Remux/Transcode planner.
  This path performs no media-object reads.
- Missing information does not produce a playback `425`. Normal negotiation
  continues through the configured media engine as viewer work. Concurrent
  misses share one flight; a viewer cancels and takes over speculative ownership
  instead of waiting for background priority.
- A successful profile is published asynchronously whether it was generated by
  background work or viewer-required negotiation.
- Namespace change events prune a profile only after the last live path with
  that immutable identity disappears. Identical aliases/copies continue to
  share it.
- `GET /api/v1/catalogue/media/{url-encoded-macha-media-id}/profile` remains an
  advisory metadata endpoint: it returns the immutable profile when available,
  or `202 profile_pending` with `Retry-After` after queueing work. Clients may
  begin normal playback negotiation without waiting for it.

viewer takeover/cancellation of a speculative scan, last-live-copy pruning, a

safe media-engine fallback.

## Remaining UAT

Use ES-1 to measure a cold process and repeated session for a profiled immutable
file, proving no probe/source reads on the hit. Exercise one genuine miss and a
same-key retry, proving normal negotiation succeeds, one scan is persisted, and
later admission uses it. Record start and seek latency separately; stored codec

may still be needed for consistently fast arbitrary seeks.

## Immediate deployed smoke UAT

On ES-1, a previously persisted 4,166-second Matroska profile was returned by
the profile endpoint in 0.37 ms. A forced-Direct session using it completed in
17.0 ms end to end from the local ES host; the server trace reported an
immutable-profile hit with `lookup_ms=0`, Direct selection and total admission
`elapsed_ms=0`, with no probe/source-read entries. Repeating the same POST with
the same idempotency key completed in 0.8 ms and returned the same session ID
and generation. The temporary session was then deleted.

The same log window contained a genuine miss for a different immutable file.
It continued through normal viewer media-engine inspection rather than
returning `profile_pending`; the resulting profile was subsequently available
from the profile endpoint with HTTP 200. This is useful smoke proof of both the
hit and persist-after-miss paths, but it does not replace the remaining
multi-node cold-process/start/seek UAT above.
