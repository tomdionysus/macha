## How FUSE and hydration reach Macha's store

FUSE never holds `DistributedStore` (`ffh:540-548`). It reaches it through four doors:

- kernel reads: `FuseFrontend::read_impl` (`ff:5910-6068`) opens a `ReadHandle` with `FileSystem::open_read(entry, path,
  false, FrameType::loader)` (`ff:5993-5994`, `:6001-6002`; `fs:2192-2198`), whose `read` calls
  `DistributedStore::get_shared` per extent (`fs:116-154`) on the FUSE broker's read worker;
- publication: the data workers (`ff:3876-4190`) drive a `PublicationWriter` opened by
  `PublicationTarget::open_publication` (`ff:3575-3580`), which is `FileSystem::open_write(..., publication_generation, ...)`
  (`fs:2204-2210`); `WriteHandle` makes the store calls (`put_deferred`, `get`, `cache_local`, `durability_barrier`,
  the activity clocks), partly on FileSystem's extent executor threads (`fs:1380-1433`);
- the namespace: `apply_namespace_batch`, the snapshot views and `namespace_nodes()` (control objects through
  `ensure_control_local`, `fsh:612-614`, `src/metadata/namespace_control_store.cpp:38-44`, `ds:2292-2295`);
- figures: `idle_for` (`fsh:621-623`), `reachability_epoch` (`fs:2200-2202`), `logical_capacity` (`fs:2412-2438`),
  `extent_size`, `write_progress`.

Hydration holds `DistributedStore&` directly (`hyh:162`, `:218`): `hydration_available`, `locally_available`,
`hydrate`. FUSE feeds it hints (`ff:6716-6747`, registered at `fsub:61`).

Dagda today: `Context::Objects` offers a content-addressed write and a read, each with a mandatory positive deadline
(`CTX:29-31`, `CTXH:190-196`), an async form posting to the caller's executor and a blocking form that is a wait on it
(`CTX:36-43`); both run on the store's worker pool (`DS:1146-1165`, `:1760-1766`), four threads by default
(`DSH:273-275`) taking jobs FIFO from one unbounded queue whatever their class (`DS:645-668`). `Context::Tickets::wait`
takes one ticket (`CTXH:385-390`). Everything else below is a part of `Node` (`node.h:361-379`, "for an owner's
maintenance and for tests"): a GAP until Context serves it (the route, 2026-11-14).

## 1. Kernel reads: `read_impl` -> `ReadHandle` -> `get_shared`

The FUSE request: `fa:322-346` passes libfuse's `buf` as a span to `FuseFrontend::read` (`ff:6070-6079`), which
`dispatch`es (`ffh:559-648`) to a broker read worker with the deadline `min(timeouts.read, absolute_request_timeout)`
(`ffh:563-564`) and a shared cancel flag. A read stays cancellable once running (`ffh:565-566`, `:600-601`); on expiry
`dispatch` sets the flag and throws ETIMEDOUT at once (`ffh:633-637`) while the worker may still be inside `read_impl`.

## 2. Publication: `data_loop` -> `replay_data_quantum` -> `PublicationWriter`

The data worker replays the spool into a writer quantum by quantum (`ff:3492-3758`), yielding to the loader
admission between chunks (`ff:3605-3613`, `:3617-3619`, `:3636-3638`); `drain_staging` at each yield
(`ff:3608`); `prepare_write` / `prepare_commit` stage the old generation within the quantum (`ff:3646-3650`,
`:3704-3707`); `commit` (`ff:3713`). Errors: ESTALE drops the writer and replays from the spool (`ff:4036-4039`,
`:4072-4075`); FsError codes EAGAIN, EIO, EINTR, ETIMEDOUT, network codes, EBUSY and every non-FsError exception are
retryable with per-inode backoff (`ff:196-218`, `:4077-4105`), parked past the budget with the target's reachability
epoch (`ff:4097-4101`); a terminal ENOENT abandons the spool generation (`ff:4044-4066`). `fsync` waits until
`published_data_sequence` covers the durable prefix, "advanced only after PublicationWriter::commit(): cluster-durable
at this watermark" (`ff:2236-2264`, `:6293-6307`).

## 7. Gaps for Dagda, ranked

- S1. An owned cancel token for the async forms. `ReadOptions::cancelled` and `WriteOptions::cancelled` are raw

## 8. Rewrites in Macha

Designed once, for the port, so the low-level FUSE move after it only changes the libfuse-facing adapter.

1. Reads return owned parts. `ReadHandle` (`fs:104-197`) holds `dagda::Context&` and returns the extent slices it
   reads as `ObjectData` (shared, owned) instead of copying into a caller span; `read_impl` (`ff:5910-6068`) builds its
   reply from those slices and spool bytes in a Macha-owned buffer and copies into libfuse's buffer only on the worker,
   before `dispatch` returns. With the low-level API the same parts go out by `fuse_reply_iov`, the request holding
   them until the reply. `dispatch`'s timed-out-while-running branch for reads (`ffh:633-637`) stops leaving a writer
   behind. Rows 1, 4. Needs S1, P5 and F1 before the async form is used.
2. The read's cancel and outcome. The request owns its token (interrupt or deadline) and maps the outcome to ECANCELED
   or EINTR, ETIMEDOUT, EIO without reading its own clock (`fs:133-139` goes). Rows 3, 6.
3. Publication on tickets. `DurabilityBatch` becomes `std::vector<dagda::Ticket>` (`fsh:265-270`); `put_deferred`
   becomes a Context deferred write (content-addressed for new extents, known-id for rebuild and re-put); the commit
   waits on all tickets at once; the typed loss replaces `unsatisfiable` and the local `data().get`; evidence maps to
   FsError codes in one place. FileSystem's extent executor stays and calls the blocking form on its own threads.
   Rows 9-17, 21.
4. Hydration on Context. `CacheHydrator` and `HydrationManager` take `dagda::Context&` (`hyh:161-234`); `hydrate` gets
   `ReadOptions{frame, stripe, cancelled}` with the hydrator's stop flag, so stop no longer waits out transfers.
   Rows 22-25.
5. Clocks and figures through Context: loader activity on reads and replay writes, `idle_for` in
   `ViewerWeightedAdmission`, the reachability epoch (as a change notice, so the parked recheck poll at `ff:3905-3910`
   goes), the capacity for `statfs`, the extent size. Rows 8, 18, 20, 27, 30, 31.
6. The namespace through head spaces: with the metadata section, FUSE's refresh adopts from `Heads::watch` and
   `Heads::changed` rather than a node store from FileSystem. Rows 28, 29.
7. Memory through Dannan's contract (row 32): FUSE's request, operation and publication reservations and the recovery
   `restore`, on the ledger the store's reads are charged to.
