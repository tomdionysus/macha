# Macha's filesystem layer onto Dagda: the callers' map

Section of the call-by-call map from Macha's store calls to Dagda (2026-11-14), the callers' side, subsystem
`src/filesystem/*` (FileSystem, ReadHandle, WriteHandle/PublicationWriter, the census and media index, the
hydrator). Macha side: develop f0597a4, extracted read-only at `dagda/build/macha-f0597a4/`. Abbreviations:
`fs` = `src/filesystem/filesystem.cpp`, `fsh` = `src/filesystem/filesystem.hpp`, `hy` = `src/filesystem/hydration.cpp`,
`ds`/`dsh` = Macha's `src/cluster/distributed_store.cpp`/`.hpp`, `ncs` = `src/metadata/namespace_control_store.cpp`.
Dagda side: branch `feature/macha-store-gaps` at 0d9a4ff, working tree clean: `DS`/`DSH` =
`dagda/store/distributed_store.cpp`/`.h`, `CTX`/`CTXH` = `dagda/context.cpp`/`.h`, `NODE` = `dagda/node.h`,
`RC` = `dagda/ledger/reference_counts.h`, `SP` = `dagda/store/storage_pool.h`. Macha tests are `tests/<file>:<line>
<name>`; Dagda tests are `dagda/test/<file>:<line> Suite.Case`. Every claim was read in code; what was not is marked
UNVERIFIED. "None found" for a test means a name and keyword search over `tests/` and `dagda/test/` found none.

What Context offers today (CTXH:182-224, 379-396): `Objects::write` (content-addressed, CTX:120), `Objects::read`,
`Objects::has` (pool only, CTX:143 -> DS:593), `Objects::remove`, and one ticket's `status/wait/wait_complete`. Every
call takes a positive deadline (CTX:29-31) and runs on the store's workers (`workers = 4`, DSH:275); the blocking forms
are `await` on that completion (CTX:35-43), throwing `std::runtime_error` if it is 5 s late. Context also has Heads,
Claims, Leases, Domains, none of which the filesystem layer calls. Everything else below is reachable only through
`Node`'s parts (NODE:361-384, "for an owner's maintenance and for tests"), so by the route's rule it is a GAP until
Context serves it. The verdict column gives both: the Context verdict, then what the Node part does.

Not in this section (read, and not store calls): `local_.replica()` (fs:2380-2405, the metadata replica: metadata
section), `m_`/`metadata_server_` (metadata), `membership_.active()` (fs:2413, Dannan), `playback_` (media).

## Rewrites in Macha (src/filesystem)

1. FileSystem, ReadHandle, WriteHandle, CacheHydrator and HydrationManager hold `dagda::Context&` (Node parts only
   until Context serves gap 7); `LocalState&` and `DistributedStore&` go; `FileSystem::store()` is removed and its
   torrent caller moves to Context; `namespace_nodes()` is built over Dagda's CONTROL reads (or Heads).
2. ReadHandle keeps `ReadResult::object` as its cached extent, passes the remaining duration and the cancel token,
   and maps the outcome to ECANCELED, ETIMEDOUT or EIO; it keeps releasing the previous extent before the next.
3. WriteHandle replaces `DurabilityBatch` with `std::vector<dagda::Ticket>`; `StagedExtentResult` carries a ticket;
   flush, the pipelined extent task (still on the filesystem's own executor) and `rebuild_step` write through Context
   and read `WriteEvidence`: `cancelled` -> EINTR, `holders() == 0` -> `FsStorageUnavailable`. No store exception type
   leaves the filesystem, so ingest's `storage_unavailable` classification (`ingest.cpp:1627-1628`) keeps working
   through `FsStorageUnavailable`.
4. `commit` waits on all of the handle's tickets at once; all met -> metadata commit; a copy refused as absent (by
   Dagda's code, gap 1) -> re-put from this node's pool copy, replace the ticket, wait again; still pending -> EIO;
   no local copy -> ESTALE. The deadline is the work context's when set, else 30 min (`object_transfer_call`), Macha's
   per-call bound today. The "re-put" info line and `stage=durability-barrier` debug line stay.
5. `truncate_file` reads through Context and writes through Context, mapping a failure to `FsStorageUnavailable`
   (today a raw `StorageUnavailable` escapes it).
6. The hydrator calls Context's hydrate with `ReadOptions{frame, stripe, cancelled}`, the cancel being its stop flag,
   so `request_stop` abandons fetches in flight.
7. The census stays Macha's, over Dagda's reference counts; `maintenance_objects_cached` becomes Macha's
   `ReachabilityProvider::inventory`, filling `Reachability` from what `MaintenanceObjects` holds today (with the
   maintenance and composition-root sections).
8. The activity notes and `idle_for` go through Context's activity form; `logical_capacity` and `reachability_epoch`
   through theirs.
