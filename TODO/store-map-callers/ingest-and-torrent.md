## How this code reaches the store

Exactly three direct store touches, all in the torrent subsystem (a search of both directories for `store()`, `put`,
`get`, `has`, `held_here`, `cache_local`, `hydrate`, `retain_`, `durability_barrier`, `local_.`, `data()`,
`data_resources_`, `claims`, `ledger` found no others):

- `fs->store().put(bytes, FrameType::loader, &abort)`, `src/torrent/torrent_manager.cpp:1280` (row 1);
- `DataResourceArbiter::acquire` through `loader_admission`, `src/torrent/torrent_disk_io.cpp:988-1002`, wired at
  `torrent_manager.cpp:1271` (row 2);
- `local_.data().service_monitor().note(...)`, `torrent_manager.cpp:1325-1329` (row 3).

The ingest makes no direct store call. It reaches the store only through `FileSystem` (`open_write`, `WriteHandle::write`
and `commit`, `commit_file`, and the namespace operations), and depends on store semantics there: the extent puts, the
cache write-through, the append-tail read, the retention barrier, and the exception types it classifies (rows 5-12).

There are no store `has`/`held_here` checks anywhere in ingest or torrent: "held" in the torrent code is libtorrent's
hold (`torrent_session_policy.cpp:37`), and publication progress is in memory (`torrent_disk_io.cpp:563-576`). The
journal of published extents is a host file in the job's staging directory (`torrent_extent_journal.cpp:32-34`), not a
store object, trusted no further than the commit's retention barrier (`torrent_extent_journal.hpp:7-8`, row 10).

Common facts for the ingest rows: the ingest runs `max_concurrent_jobs` worker threads (default 10,
`src/config.hpp:364`; `ingest.cpp:840-849`); each blocks on the filesystem's calls. It opens its partial with
`open_write(temp, false, /*cache_puts*/ true)` (`ingest.cpp:2131`, again at `:2147` on a re-base), so immediate
durability (`filesystem.hpp:559-562`) and a default `DataWorkContext{}`: loader class, no deadline, no cancel token, no
budget (`src/cluster/data_work.hpp:34-37`). The only cancellation is `FileSystem::io_cancelled_`, set last in the node's
stop "so a write it cancels fails a caller already told to stop: an ingest stopped mid-put resumes rather than fails"
(`src/service/node_services.cpp:294-298`). Copy chunk 1 MiB, checkpoint 64 MiB, blocked retry 5 s
(`src/config.hpp:358-360`); production extent 4 MiB (`tests/fixtures/node-configs/fi-1.yaml`, per the DS section).
