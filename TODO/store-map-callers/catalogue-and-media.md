`Objects::read`, both with a mandatory positive deadline (CTX:29-31) and run as a worker job the blocking form waits on
(CTX:36-43, 116-141); `Objects::has` (CTX:143, the pool, DS:593); `Objects::remove`; `Claims::retain` and
`Claims::retained` (CTX:177-213); `Tickets::status/wait/wait_complete` for one ticket (CTXH:379-396); `Heads`. There is
no CONTROL object read, write, fetch or offer in `Context` at all, and no read without a deadline.

Method: every file in `src/catalogue`, `src/media`, `src/playback` was searched for every store-facing name (the store,
LocalState and its stores, the ledger, ReadHandle and `open_read`, FileSystem, retained memory, credit, activity,
hydration, cache); each hit was read in context. Files with no store call: `catalogue_hints.*` (its own JSON state
file), `cluster_unmatched.*` (a peer RPC, `cluster_unmatched.cpp:123-124`), `epub_metadata.*`, `mobi_metadata.*`

`subtitle_text.*`, `ffmpeg_log*`, `media_engine_common.cpp`, `segment_holds.hpp`. Segment caching is memory plus a spill
to the host's streaming temp path (`ms:25-131`, `pb:746`, `pb:2350-2353`), never the store. `media_engine.cpp`'s
`store_` is the in-memory `MediaSegmentStore`, not Macha's store.
